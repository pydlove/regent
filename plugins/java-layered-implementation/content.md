# Java 分层实现

先读模块边界和相邻实现，再决定代码放哪一层。不要把所有逻辑塞进一个 Service。

## 依赖方向

- `domain` 只依赖同上下文领域模型、共享领域类型和 JDK。
- `application` 编排领域对象和仓储端口，不直接写 SQL、不直接发 HTTP。
- `infrastructure` 实现仓储和外部系统端口，不反向被领域层依赖。
- `interfaces` 只调用应用服务并使用 DTO，不直接访问 Mapper 或仓储实现。
- Spring 装配放在启动模块的配置类中；核心域保持纯 Java。

## 领域建模

- 聚合根之间只保存 ID，不持有另一个聚合对象。
- 状态迁移写成带守卫的领域方法；禁止暴露 `setStatus` 或直接 UPDATE 状态绕过规则。
- 值对象优先使用 `record`，强类型 ID 不降级成裸 `Long`。
- 领域对象不使用 Lombok `@Data`，避免生成绕过不变量的 setter。
- 业务规则放在领域对象或领域服务中，应用服务只负责编排和事务边界。

## 端口与适配器

外部系统先定义端口，再在基础设施层实现：

- `codex`、Git、邮件、推送、对象存储都属于外部系统。
- 外部输出格式的解析留在适配器内，不渗入领域模型。
- 端口返回领域类型或简单值，不返回框架对象、数据库数据对象或第三方 SDK 类型。
- 外部调用失败转换成有业务含义的异常，并保留可诊断的 cause。

## 事务与一致性

- 跨聚合变更由应用服务显式编排，并在同一事务中完成。
- 不能在事务提交前启动依赖该数据的异步任务；使用事务完成回调。
- 唯一约束冲突、乐观锁失败和重复提交要有明确处理，不吞异常。
- 幂等操作先查已有结果，再决定插入或更新。

## DTO 与错误

- 对外契约只使用接口层 DTO，不序列化领域对象。
- 请求 DTO 做基本格式校验，业务校验留在领域层。
- 域规则冲突返回可理解的 4xx；未知异常记录日志但对外隐藏堆栈和敏感细节。
- 新增字段优先保持向后兼容，不随意改名或复用旧字段表达新含义。

## 代码风格

- 复用现有命名、包结构和工具，不新增无用的 Factory、Builder 或 Specification 全家桶。
- 注释只解释“为什么”，不复述代码。
- 修改后先跑核心模块单测，再跑受影响模块，最后按需要跑全量构建。
