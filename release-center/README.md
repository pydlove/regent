# Regent 发布中心

本地发布管理页面，只监听 `127.0.0.1`，不会暴露到局域网或公网。

## 启动

双击 `start.command`，或执行：

```bash
./release-center/start.sh
```

默认地址：

```text
http://127.0.0.1:12600/
```

## 发布流程

1. 输入新版本号；
2. 可填写给 Codex 的补充要求；
3. 点击“生成版本内容”，由本机 Codex 只读分析仓库并生成摘要和更新项；
4. 审核并修改预览内容；
5. 勾选确认后点击“确认发布”；
6. 构建前端和双平台安装包，写入发布清单，并按选项部署公网；
7. 提交发布文件并创建本地 Git 标签，记录提交、标签、清单摘要和产物摘要。

正式发布要求工作区干净。未提交改动、已存在的版本号或 Git 标签都会在构建前
被拒绝。发布凭证写入 `~/.regent/release-center/release-center.db`，发布任务也
保存在同一数据库中；发布中心重启后，遗留的执行中任务会标记为“已中断”，
不会再永久显示执行中。

生成成功的预览会写入 `~/.regent/release-center/draft.json`。刷新页面后会恢复版本号、
摘要、更新项和发布选项，不需要重新调用 Codex；“我已核对”勾选不会恢复，仍需人工重新确认。
发布成功后会清除草稿；如果生成后 Git 提交已经变化，或者工作区出现未提交改动，页面会阻止发布。

发布页面支持：

- 同步部署公网前端；
- 服务器升级同样要求干净工作区，避免直接发布未提交代码；
- 查询最近发布凭证和最近任务，点击任务可重新打开日志；
- 实时查看构建与发布日志；
- 发布失败时保留日志并终止流程。

## 维护

```bash
./release-center/status.sh
./release-center/stop.sh
```

日志位置：

```text
~/.regent/logs/release-center.log
```

发布中心数据库：

```text
~/.regent/release-center/release-center.db
```
