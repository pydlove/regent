# 插件能力库设计

> 目标：把任务中反复出现的组件、代码片段和接入说明沉淀为可复用能力包。
> 任务执行时按固定版本读取插件内容，AI 优先复用已有实现，不再每次重新生成。

## 一、边界

第一阶段把插件定义为**可版本化的文本/代码能力包**，不是由 Regent 进程直接执行的二进制插件：

- 插件内容可以是 Java/Python/Shell 代码、协议说明、配置模板或接入步骤；
- 平台不加载、不编译、不执行插件代码，只把内容交给任务执行器；
- 插件不保存数据库密码、Token、证书等凭据，运行凭据仍由环境信息注入；
- 插件不能绕过分级决策、项目规则和任务验收标准。

这个边界先用最低的运行时风险解决“重复生成同一组件”的问题。后续若需要真正的二进制插件，
应另行增加签名、依赖隔离、进程沙箱、权限清单和安装卸载流程，不能把任意 JAR 直接塞进主进程。

## 二、领域模型

### Plugin 聚合

`Plugin` 保存名称、说明、标签、启停状态和当前版本。每次保存内容都会生成新的
`PluginVersion`，版本号单调递增，内容以 SHA-256 摘要标识。

不变量：

- 插件名称平台内唯一；
- 内容不能为空，单版本最大 256 KiB；
- 文件名只用于展示，不允许包含路径分隔符；
- 停用插件不能绑定新任务；
- 修改内容不能覆盖历史版本。

### TaskPlugin 绑定

`task_plugin` 保存任务、插件和固定版本号，不跟随插件当前版本漂移。插件升级后：

- 已绑定任务继续使用原版本；
- 用户重新选择插件后，任务改绑当前版本；
- 插件停用后，已绑定任务在下次执行前失败关闭，要求移除或换绑。

任务开始执行后禁止改绑。执行编排在开局读取一次绑定并固定到内存快照，避免执行中途换版本。

## 三、数据表

| 表 | 职责 |
|---|---|
| `plugin` | 插件元数据、启停状态、当前版本号 |
| `plugin_version` | 不可变内容版本、文件名、SHA-256、创建时间 |
| `task_plugin` | 任务与插件固定版本的绑定 |

迁移脚本：`V17__plugin_library.sql`。

## 四、执行注入

内部 Codex 与外部执行者使用同一份 `PluginContext`：

1. 任务开始时读取 `task_plugin` 与对应 `plugin_version`；
2. 校验绑定插件当前仍处于启用状态；
3. 生成“已绑定插件”指令段，声明优先复用、不要重写；
4. 内部执行器把该段拼进 `codex exec` 的 stdin 指令；
5. 外部执行者工作包增加 `plugins` 数组，包含版本、文件名、摘要和完整内容；
6. 内部执行事件流写入 `platform.plugins`，只记录插件 ID、版本和摘要，不重复保存全文。

## 五、API

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/plugins` | 插件列表，不返回全文 |
| `GET` | `/api/plugins/{id}` | 插件详情与当前版本全文 |
| `POST` | `/api/plugins` | 新增插件 |
| `PUT` | `/api/plugins/{id}` | 更新元数据与内容并生成新版本 |
| `PUT` | `/api/plugins/{id}/enabled` | 启用或停用 |
| `GET` | `/api/tasks/{taskId}/plugins` | 任务当前绑定版本 |
| `PUT` | `/api/tasks/{taskId}/plugins` | 整体替换任务绑定 |

## 六、Kafka 示例

1. 在环境页添加 `KAFKA_BOOTSTRAP_SERVERS`、`KAFKA_TOPIC`、`KAFKA_USERNAME`、`KAFKA_PASSWORD`；
2. 在插件页新增“Kafka 读取组件”，导入已经验证过的消费者代码、序列化配置和示例入口；
3. 新建任务时绑定该插件，任务指令只描述“读取哪个主题、筛选条件、输出到哪里”；
4. 执行时 AI 直接复用插件代码，凭据从环境变量读取，不进入插件正文。

## 七、后续演进

- 支持多文件包与目录清单；
- 支持版本差异、升级提示和批量换绑；
- 支持插件使用统计与失败反馈；
- 若需要执行型插件，增加独立进程、权限清单、签名验证与审计日志；
- 对大型插件增加按需检索，避免把全部内容一次性塞进模型上下文。
