# 移动端公网中继设计

## 目标

手机通过公网服务器访问 Regent 网页，并完成：

- 查看任务、决策和 Bug；
- 新建、编辑、派发和终止任务；
- 批准或拒绝 L2/L3 决策；
- 上传任务与 Bug 图片；
- 让真正的 Regent 服务继续只运行在本地电脑，因为本机需要调用 `codex`。

约束是本地电脑没有公网 IP，服务器不能主动连接本地电脑；本地电脑可以主动访问服务器。

## 方案

公网服务器不运行 Regent 业务服务，只运行一个无状态中继：

```text
手机浏览器
   |
   | HTTPS
   v
Nginx（HTTPS + Basic Auth + 静态前端）
   |
   | http://127.0.0.1:8788/api
   v
regent-relay server
   ^
   | 本地主动发起 HTTPS 长轮询
   |
regent-relay connector
   |
   | http://127.0.0.1:8787
   v
本地 Regent（codex / Git / MySQL 都留在这里）
```

这条路仍然是单向的：

1. 手机请求先到服务器；
2. 服务器把请求放进有界队列；
3. 本地连接器主动向服务器领取请求；
4. 连接器访问 `127.0.0.1:8787` 的 Regent；
5. 连接器把状态码、响应头和响应体主动回传服务器；
6. 服务器把结果返回手机。

不需要公网 IP、路由器端口映射、反向 SSH 隧道或 VPN。服务器始终不知道本地电脑的地址，
也不能主动建立到本地的连接。

## 组件

`regent-relay` 是一个零第三方运行时依赖的 Java 17 可执行 JAR，提供两种模式：

```bash
java -jar regent-relay.jar server
java -jar regent-relay.jar connector
```

### server

只监听 `127.0.0.1:8788`，由 Nginx 暴露：

| 地址 | 作用 |
|---|---|
| `/api/**` | 接收手机请求，等待本地连接器返回结果 |
| `/api/relay/connector/poll` | 本地连接器长轮询领取请求 |
| `/api/relay/connector/response` | 本地连接器回传响应 |
| `/health` | 中继与连接器在线状态 |

请求队列有容量上限，公网请求有固定超时，连接器离线时直接返回 `503`，
不会无限堆积内存。

### connector

连接器运行在本地 Regent 所在电脑，只做三件事：

1. 主动访问公网服务器的 connector 接口；
2. 把领到的请求转发给 `http://127.0.0.1:8787`；
3. 把响应主动回传服务器。

连接器不监听端口，因此服务器没有反向访问本地电脑的能力。

## 安全边界

- **Regent 继续绑 `127.0.0.1`**：即使中继配置错误，Regent 也不会直接监听公网。
- **中继 server 继续绑 `127.0.0.1`**：只有 Nginx 能访问它，避免绕过 HTTPS 与认证。
- **Nginx 必须启用 HTTPS**：手机与连接器都会通过公网传输请求体、响应体和共享密钥。
- **Nginx Basic Auth 保护手机页面与业务 API**：只给个人设备使用，不要裸奔到公网。
- **连接器使用独立共享密钥**：密钥只放在服务器 `relay.env` 和本机 `~/.regent/relay-connector.env`，
  不进入仓库、不写进前端，也不能与 Nginx 密码复用。
- **写请求要求 `X-Regent-Relay-Request: 1`**：浏览器同源请求会带，跨站表单无法设置该头，
  用于降低 Basic Auth 场景下的 CSRF 风险。
- **请求头有白名单**：`Authorization`、`Cookie`、`Host` 等不会透传给本地 Regent。
- **响应头有白名单**：只保留内容类型、附件和缓存相关字段，不把本地 Cookie 或分块传输头带回。
- **路径限定为 `/api`**：连接器不会把服务器投递的任意路径转换成对本机文件或其他服务的 SSRF 请求。

这套防护面向个人单用户部署。要开放给多人时，需要把 Basic Auth 换成正式登录、会话和细粒度授权，
并重新审查本地目录浏览、附件和任务写接口。

## 部署

### 1. 服务器

```bash
export REGENT_SERVER_IP=1.2.3.4
export REGENT_SERVER_USER=root
export REGENT_SSH_KEY=~/.ssh/id_rsa
./deploy/remote/deploy.sh
```

随后按 `deploy/remote/nginx/regent.conf.example` 配置域名、证书、htpasswd 和反代，
再 reload Nginx。

### 2. 本地

```bash
./deploy/local/connect-relay.sh          # 读取服务器共享密钥并写入 ~/.regent/relay-connector.env
./deploy/local/relay-agent.sh install    # 交给 launchd 常驻：手机随时打得开的前提
./deploy/local/start-all.sh              # 后端 + 前端
```

`deploy/remote/deploy.sh` 第 6/7 步会先启动远端中继，再调用 `connect-relay.sh`
完成配对并强制确认连接器上线；正常部署流程下无需单独执行，它只用于
「不重新部署、仅重配连接器」的场景。
连接器配置里只存服务器地址与共享密钥两项关键信息，文件权限 600，永不入库。

手机上访问 `https://你的域名/`。首次浏览器会要求输入 Nginx Basic Auth 账号密码。

## 失败表现

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面 401 | Nginx Basic Auth 未输入或密码错误 | 重新输入 htpasswd 中的账号密码 |
| API 返回 `RELAY_OFFLINE` | 本地连接器未运行或断线 | `./deploy/local/relay-agent.sh status`；没配对过就 `./deploy/local/connect-relay.sh` |
| API 返回 `RELAY_TIMEOUT` | 本地 Regent 长时间未响应 | 查看后端日志与任务执行状态 |
| API 返回 `LOCAL_REGENT_ERROR` | 本地 Regent 未启动或接口失败 | 检查 `http://127.0.0.1:8787/actuator/health` |
| 图片或附件 413 | Nginx/中继请求体上限过小 | 同步调整 `client_max_body_size` 与 `REGENT_RELAY_MAX_BODY_BYTES` |

## 明确不做

- 不把 MySQL、codex 或项目工作区迁到公网服务器；
- 不让公网服务器持有数据库密码；
- 不做服务器到本地的反向连接；
- 不把共享密钥编译进前端，也不允许通过浏览器读取。
