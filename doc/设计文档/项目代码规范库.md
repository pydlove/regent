# 项目代码规范库详细设计

> 状态：已实现
> 归属：`execution` 上下文中的项目文件库能力

## 1. 目标

文件库是项目资料资产的统一入口。首个专业化子库是“开发规范库”，后续需求文档、设计文档、测试资料可以沿用相同的项目归属、权限和物理文件存储能力。

开发规范不是普通附件，必须满足：

- 归属于项目，不跨账号；
- 支持稳定条目与不可变版本；
- 可启用、停用、默认引用和跨项目复制；
- 任务创建时固定规范版本；
- 派发前验证文件存在且摘要一致；
- 执行器每轮执行都能拿到规范正文；
- 历史任务不受规范后续更新影响。

## 2. 信息架构

```text
文件库
├── 开发规范
└── 通用文件
```

后续可以增加需求文档、设计文档、测试资料分类，但每类资料拥有各自的业务关系和生命周期，不把语义全部堆到文件库主表。

## 3. 数据模型

### 文件库

`file_library_document` 增加 `library_type`：

- `GENERAL`
- `DEVELOPMENT_RULE`
- `REQUIREMENT`
- `DESIGN`
- `TESTING`

项目内的内容去重键调整为 `(project_id, library_type, content_hash)`，不同子库互不误复用。

### 开发规范

`code_standard` 保存稳定条目：

- 项目归属
- 名称、说明、适用范围
- 启用、默认引用、排序
- 归档状态
- 跨项目复制来源

`code_standard_version` 保存不可变版本：

- 规范 ID
- 版本号
- 文件库文档 ID
- SHA-256

`task_code_standard` 保存任务快照：

- 任务 ID、规范 ID、版本 ID
- 名称、版本号、文件名、类型、大小、摘要、存储路径
- 来源项目

## 4. 上传与版本

- 开发规范只接受可稳定读取的 UTF-8 文本：`.md`、`.txt`、`.yaml`、`.yml`、`.json`、`.xml`。
- 单份默认上限 512 KB，可通过 `regent.code-standards.max-bytes` 调整。
- 新建规范生成 `v1`。
- 上传相同内容不产生新版本。
- 上传不同内容生成下一个版本，旧版本不覆盖。
- 归档只改状态，不删除物理文件。

## 5. 跨项目复制

- 来源项目和目标项目都必须属于当前账号。
- 默认复制所选规范的当前版本。
- 目标项目得到独立条目和独立文件记录。
- 来源规范后续更新不会同步。
- 相同内容自动跳过。
- 同名不同内容默认跳过；可切换为自动重命名。
- 任一写入失败时整批回滚，已落盘但未入库的文件会补偿删除。

## 6. 任务关联

新建任务时：

- 自动选中目标项目中“已启用且默认引用”的规范。
- 用户可以取消或追加本次选择。
- 规范选择随创建任务请求提交。
- 后端在同一事务中创建任务与 `task_code_standard` 快照。
- 需求和 Bug 派生任务通过 `TaskStandardBinder` 绑定默认规范。

后续任务：

- 决策恢复、失败重试、续跑继续使用原快照。
- 规范库更新不改变已有任务。
- 已开始执行的任务不能静默切换规范版本。

## 7. 执行链路

派发前：

- 校验每条任务规范的文件存在。
- 校验实际内容 SHA-256 与快照一致。
- 校验文件是可解码的 UTF-8 文本。
- 校验本次任务全部规范总大小不超过 `regent.code-standards.max-prompt-bytes`。

执行时：

- 在提示词中加入“项目开发规范”强制约束区块。
- 注入规范名称、版本、文件名、SHA-256 与完整正文。
- 内部 Codex 与设备代理使用同一份正文，不依赖双方共享文件系统。
- 自动决策续跑、外部执行者继续执行时重新注入规范。
- 规范缺失或摘要不一致时失败关闭，禁止无规范继续执行。

## 8. 界面

文件库页：

- 左侧分类：开发规范、通用文件。
- 开发规范列表展示范围、当前版本、默认引用和启停状态。
- 支持上传、编辑元数据、版本记录、下载、启停、归档和跨项目复制。

新建任务：

- 显示项目开发规范及本次引用数量。
- 默认勾选默认引用项。
- 规范库读取失败时禁止创建任务，避免静默漏用。

任务详情：

- 展示任务实际使用的规范快照。
- 每项显示名称、版本、文件名和大小，并可下载。

## 9. 审计

运行事件 `platform.code-standards` 记录任务本次使用的规范 ID、版本 ID、版本号、名称和摘要，便于执行复盘和问题追踪。

## 10. 测试

- 领域单测：上传、版本、复制、默认快照、历史任务版本隔离、文件缺失拒绝执行。
- 集成测试：Flyway 迁移、真实 MySQL 往返、跨项目复制、任务快照与正文注入。
- 前端测试：TypeScript 类型检查、UI 规范检查、生产构建。
