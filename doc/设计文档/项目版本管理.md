# 项目版本管理

| 项目 | 内容 |
|---|---|
| 产品版本 | Regent_V1.0.6 |
| 文档版本 | v1.0 |
| 范围 | 项目版本策略、部署版本解析与追溯 |

## 一、目标

项目版本不是一张孤立的手填字段，而是连接任务、Git 提交与部署记录的事实标识。

需要回答三个问题：

1. 当前项目应发布哪个版本？
2. 某次部署实际发布的是哪个版本？
3. 这个版本对应哪次任务、审阅和 Git 提交？

## 二、设计原则

- 项目保存版本策略，部署记录保存版本事实。
- Git Tag 是默认版本来源，避免手填值与代码提交漂移。
- 没有 Git Tag 时允许使用项目备用版本，保证旧项目仍可发布。
- 只有无法维护 Tag 的项目才使用手动固定版本。
- 版本解析失败不阻断现有部署，但必须明确显示“未标记版本”。
- 历史部署记录保存版本快照，后续修改项目设置不能回写历史。

## 三、版本来源

### GIT_TAG

平台读取当前 `HEAD` 指向提交上的 Git Tag，按版本排序取第一个合法 Tag。

例如：

```text
v1.6.1
```

如果当前提交没有 Tag，则使用项目备用版本。备用版本也为空时，部署记录版本为空，并在界面显示“未标记版本”。

### MANUAL

平台直接使用项目设置的固定版本。手动模式必须填写版本，适合无法维护 Git Tag 的旧项目或非代码项目。

## 四、数据模型

### project

| 字段 | 含义 |
|---|---|
| `version_source` | `GIT_TAG` / `MANUAL` |
| `fallback_version` | Git Tag 不可用时使用；手动模式必填 |

### deployment_run

| 字段 | 含义 |
|---|---|
| `project_version` | 本次部署入队时解析出的版本快照 |
| `version_source` | `GIT_TAG` / `MANUAL` / `FALLBACK` / `NONE` |

`deployment_run` 已经保存项目、任务、审阅快照与人工结论，增加版本后形成完整交付链：

```text
任务 → 审阅 → Git 提交 → 项目版本 → 部署执行
```

## 五、接口

### 查询项目版本

```text
GET /api/projects/{id}/version
```

响应示例：

```json
{
  "version": "v1.6.1",
  "source": "GIT_TAG",
  "available": true,
  "message": "使用当前提交的 Git Tag"
}
```

项目创建和更新接口增加：

```json
{
  "versionSource": "GIT_TAG",
  "fallbackVersion": "v1.6.0"
}
```

部署接口不需要客户端提交版本。后端在创建 `deployment_run` 时重新解析并记录，避免客户端伪造或在确认后代码发生变化。

## 六、用户体验

- 项目编辑弹窗增加“版本来源”和“项目版本/备用版本”。
- 项目详情显示当前解析版本及来源说明。
- 部署确认弹窗显示“本次发布版本”。
- 部署执行记录显示版本，没有版本时显示“未标记版本”。
- 帮助中心说明 Git Tag、备用版本与手动模式的区别。

## 七、约束

- 版本文本最长 64 个字符。
- 允许字母、数字、点、下划线、加号和连字符。
- 手动模式不允许空版本。
- Git Tag 读取只执行固定 Git 命令，不接受前端传入命令。
- 版本解析在部署入队事务内完成，版本和部署快照一起落库。
