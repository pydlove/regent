# Regent 手机 App 与多账号设备隔离需求说明书

| 项目 | 内容 |
|---|---|
| 需求编号 | REG-V105-MOB |
| 优先级 | P0-1 |
| 文档版本 | v1.5 |
| 状态 | 产品决策已确认，技术评审已完成，P0 技术验证进行中 |
| 编写日期 | 2026-10-21 |
| 依赖需求 | V1.0.4 执行可靠性、设备租约与公网中继 |
| 关联能力 | 任务、决策、文件库、设备代理、Runtime、公网中继 |

## 一、背景与问题

Regent 已具备桌面工作台、设备代理和公网中继。用户离开电脑后，理论上可以通过手机浏览器访问，
但仍存在四个实际问题：

1. 手机浏览器不是正式产品入口，没有系统推送，也不会在桌面图标、通知栏和深链中形成稳定体验。
2. 用户收到 L2/L3 决策后必须主动打开网页，容易错过等待人工处理的执行。
3. 新建任务、上传文档、查看状态、停止或重试等操作在桌面页面中仍然拥挤。
4. 多账号场景缺少产品化的“手机安装、执行电脑、项目、任务”归属说明，存在把 A 的任务下发到 B
   电脑上的风险。

本需求将手机端收敛为一个可下载、可推送、可远程操作的正式 App，并把多账号设备隔离作为不能妥协的
安全底线。

## 二、目标

### 1. 业务目标

- 用户无需打开电脑，也能通过手机下发任务并观察执行。
- 等待决策、设备失联、执行卡住和任务失败能够主动通知用户。
- 手机可以完成批准、驳回、停止、重试和继续任务。
- 多用户共用同一个 Regent 服务时，账号 A 的手机只能操作账号 A 的项目、任务和执行电脑。
- App 不获得超出 Regent 业务接口的电脑控制能力。

### 2. 用户体验目标

- 用户打开 App 后，首屏能回答“主机是否在线、任务是否正常、有没有等我处理的事”。
- 用户从收到推送到完成一次决策，不需要回到电脑旁。
- 新建任务只需选择项目、输入指令、按需上传文档，然后立即派发或加入队列。
- 离线、休眠、连接器断开和 Codex 不可用分别有明确原因和处理建议。
- 切换账号后，旧账号的数据、通知和草稿不能残留。

### 3. 非目标

- 不在手机端执行 Codex。
- 不把执行电脑变成公网可访问的桌面。
- 不支持跨账号共享项目和设备。
- 不实现团队 RBAC、组织架构和多级审批链。
- 不实现关机状态下的远程执行。
- 不在首版实现平板、车机、手表等额外终端形态。

### 4. 品牌表达

- 固定产品标语为“电脑不在身边，AI 任务随时随地开工”。
- 首页首屏必须展示该标语，位置在首页标题与主机状态之间。
- 标语只表达产品定位，不替代主机状态、任务状态或操作提示。
- 标语中的“随时随地”指手机控制端可随时使用，不得表达为执行电脑关机或断网时仍能执行。
- 商店介绍、启动页、关于页和发布材料可以使用同一标语，不得改成含义相反的表述。

## 三、用户与角色

### 1. 项目负责人

拥有项目和执行电脑，需要经常外出。主要诉求是远程下发任务、查看进度、处理决策。

### 2. 执行者

执行电脑上的 Regent 设备代理与 Codex，不由手机直接控制。执行者只接受平台经过归属校验后派发的任务。

### 3. 同一服务上的其他账号

拥有自己的项目、任务、文件库和执行电脑。不得看到或操作当前账号的任何业务对象。

本版本只有账号本人角色，不增加管理员查看其他账号业务数据的能力。

## 四、核心概念与隔离模型

### 1. 五个隔离对象

| 对象 | 含义 | 归属键 |
|---|---|---|
| 账号 | 登录 Regent 的用户 | `user_id` |
| 手机安装 | 一台手机上的一个 App 安装实例 | `user_id + installation_id` |
| 执行电脑 | 安装连接器、设备代理和 Codex 的电脑 | `owner_id + device_id` |
| 项目 | 业务数据租户根 | `owner_id` |
| 任务 | 一次执行请求 | 通过 `project_id` 继承账号 |

### 2. 强制隔离规则

任务下发和执行必须同时满足：

```text
任务所属项目.owner_id
= 当前登录账号.user_id
= 目标执行电脑.owner_id
```

任何一项不一致时：

- 不允许下发。
- 不允许认领。
- 不允许续租。
- 不允许上报事件或结果。
- 不允许通过推送深链查看详情。
- 不向调用方暴露对象是否真实存在。

### 3. 多账号行为

- 同一账号可以拥有多台手机和多台执行电脑。
- 一台执行电脑首版只绑定一个账号。
- 用户可以主动撤销手机安装或执行电脑。
- 多人共用一台物理电脑时，必须使用不同操作系统用户，或先解除原账号绑定。
- 同一账号的不同手机可以同时查看数据，所有决策和状态操作必须幂等。

### 4. 项目与执行电脑授权

- 项目必须在目标执行电脑上单独授权。
- 授权前由设备代理检查项目目录存在、目录可访问和 Codex 可用。
- 手机只能选择“项目授权有效、执行电脑在线、Codex 可用”的设备。
- 没有可用授权设备时，任务只能保存为草稿或等待设备，不能显示为已派发。
- 账号归属一致只是必要条件，不能代替项目与电脑的可用性验证。

## 五、信息架构

App 使用四个一级入口：

| 入口 | 主要内容 |
|---|---|
| 首页 | 主机状态、正在执行、等待决策、异常提醒、最近完成 |
| 任务 | 任务列表、筛选、搜索、新建任务、任务详情 |
| 决策 | 待处理决策、已处理记录、审批详情 |
| 我的 | 执行电脑、通知设置、账号与安全、关于与更新 |

系统通知、推送和深链应能直接进入任务详情或决策详情，不要求用户逐层查找。

## 六、功能需求

### MOB-01 安装与版本信息

**要求**

- 提供 Android 和 iOS 两个平台的原生安装包。
- App 内展示产品版本和完整发布码，例如 `V1.0.5 · R100B001`。
- 首页展示固定产品标语“电脑不在身边，AI 任务随时随地开工”。
- App 展示后端最低兼容版本和当前连接状态。
- Android 支持应用内更新检查，但不能绕过系统安装确认。
- iOS 通过 App Store/TestFlight 更新。
- App 版本与后端协议不兼容时，阻止写操作并给出升级提示。

**首版支持范围**

- iOS 15 及以上。
- Android 9 及以上。
- 手机竖屏为主，兼容常见小屏和大屏设备。

**验收**

- 用户能从 App 内识别当前产品版本和发布码。
- 旧 App 连接新后端时，如协议不兼容，不会发送可能损坏数据的写请求。

### MOB-02 登录、会话与本地安全

**要求**

- 复用 Regent 现有账号登录能力。
- 使用 30 分钟 Access Token 和 30 天轮换 Refresh Token。
- Access Token、Refresh Token 只保存在 iOS Keychain 或 Android Keystore。
- 支持手动退出登录。
- 使用面容 ID、指纹或系统密码解锁；设备不支持生物识别时回退到系统密码。
- App 切到后台超过配置时间后，再次进入需要重新验证。
- 会话失效时清理业务缓存，但保留“重新登录”入口。
- 批准、驳回、撤销执行电脑和账号注销使用 5 分钟一次性 Step-up Token。
- 日志、通知和崩溃记录不得包含密码、Token、完整环境变量或敏感文档内容。

**验收**

- 未登录用户不能读取任何任务、决策、项目或设备数据。
- 退出登录后，旧会话令牌立即失效。
- 本地存储中不存在明文密码和明文长期会话令牌。

### MOB-03 多账号与手机安装隔离

**要求**

- 每个 App 安装生成唯一 `installationId`。
- 登录后，本地数据库、缓存、草稿和推送订阅均绑定当前账号。
- 切换账号前必须清理前一账号的任务草稿、项目缓存、设备缓存和深链上下文。
- 推送令牌必须解绑旧账号后再绑定新账号。
- 旧账号的通知不能在切换后继续展示为新账号内容。
- 账号隔离失败统一返回“内容不存在或已失效”，不泄露其他账号对象是否存在。

**验收**

- A 登录后看不到 B 的首页统计、任务、决策、电脑和文件库。
- A 切换到 B 后，A 的草稿和缓存不会出现在 B 的界面。
- B 登录后点击 A 的历史推送深链，不显示 A 的数据。

### MOB-04 执行电脑绑定与管理

**要求**

- 执行电脑必须先登录同一账号，再与手机完成绑定。
- 绑定使用一次性二维码或六位短期配对码，有效期默认 10 分钟。
- 配对码只能使用一次，过期、撤销或账号不一致时立即失效。
- 手机扫码后，电脑端必须展示手机名称并要求本人确认允许绑定。
- 绑定成功后，手机端展示电脑名称、平台、在线状态、最后心跳、Codex 状态和 App/Runtime 版本。
- 手机端支持重命名、查看详情和撤销执行电脑。
- 撤销后设备令牌立即失效，设备不能继续认领、续租或上报。
- App 不提供手工输入任意 `deviceId` 后直接绑定或派发的入口。

**建议配对流程**

1. 执行电脑已登录账号 A。
2. 电脑端生成一次性绑定二维码。
3. 手机 App 以账号 A 登录后扫码。
4. 服务端校验账号、配对码、设备会话和有效期。
5. 电脑端显示手机名称，由本人确认绑定。
6. 绑定成功后，手机只看到账号 A 的执行电脑。
7. 账号 B 扫码时返回“配对信息已失效”，不暴露电脑归属。

**验收**

- A 的手机不能绑定 B 已绑定的执行电脑。
- 过期配对码无法重试成功。
- 撤销执行电脑后，旧设备令牌立即无法调用设备接口。

### MOB-05 首页与主机状态

**要求**

首页首屏必须展示：

- 当前账号。
- 当前选中的执行电脑。
- 执行电脑在线状态。
- 主机状态变化时间。
- 后端、连接器、设备代理、Codex 四个健康项。
- 正在执行任务数量。
- 等待决策数量。
- 等待设备或异常数量。
- 最近一次任务变化。

主机异常时必须区分：

| 状态 | 用户文案 |
|---|---|
| 电脑离线 | 执行电脑已离线，请检查电源和网络 |
| 后端停止 | 执行电脑在线，但 Regent 服务没有运行 |
| 连接器断开 | Regent 已运行，但公网连接器断开 |
| 设备代理停止 | Regent 已运行，但设备代理没有上线 |
| Codex 不可用 | 执行电脑在线，但 Codex 未安装或无法启动 |
| 状态未知 | 信息不足，请稍后刷新或查看执行电脑 |

**验收**

- 任一健康项异常时，首页不能仍显示“全部正常”。
- 用户无需查看技术日志即可知道下一步应该检查什么。

### MOB-06 新建任务

**要求**

- 选择当前账号下的项目。
- 只展示该项目已授权且当前可用的执行电脑。
- 输入任务指令，支持语音转文字。
- 支持上传图片和文档。
- 展示文件大小、上传进度和失败原因。
- 每份文档可选择“保存到文件库”。
- 可选择文件库已有文档并绑定到本次任务。
- 可选择优先级。
- 支持“立即派发”和“加入队列”。
- 支持系统返回键和意外退出后的草稿恢复。
- 提交时必须在服务端重新校验项目归属、电脑归属和任务状态。
- 提交时必须在服务端重新校验该项目与目标电脑的授权仍然有效。

**验收**

- 手机可以独立完成一次文字任务下发。
- 手机可以上传文档并让任务执行时读取。
- A 不能选择或提交到 B 的项目。
- 网络失败时不会把任务误显示为已创建。

### MOB-07 任务列表与任务详情

**要求**

任务列表：

- 默认按最近更新倒序。
- 支持状态、项目和关键字筛选。
- 不展示其他账号任务。
- 首页与任务页的状态统计口径一致。

任务详情：

- 展示标题、项目、业务状态、健康状态、当前阶段、执行电脑、开始时间和最后活动时间。
- 展示最近事件形成的人类可读时间线。
- 技术日志默认折叠。
- 展示关联文档、运行记录、决策、部署和 Bug。
- 根据状态提供停止、重试、继续、更换设备和调整方向。
- 不可用操作必须说明原因。

**验收**

- 用户不展开原始日志也能判断任务是否正常、为何停下、下一步做什么。
- 刷新页面或重新打开 App 后，状态与后端一致。

### MOB-08 远程任务操作

**要求**

- 停止、重试、继续、调整方向、更换设备必须调用现有应用服务，不允许 App 直接修改状态。
- 操作前展示影响说明。
- 停止活动任务必须二次确认。
- 重复点击必须幂等，不能产生多个有效执行。
- 每个创建、派发、决策、停止、重试和撤销动作必须携带唯一 `clientRequestId`。
- 服务端按账号保存幂等结果 24 小时，App 自动重试复用原请求 ID。
- 同一请求 ID 携带不同动作或请求体时必须拒绝，不能返回旧动作结果。
- 操作结果必须落入审计记录，包含账号、手机安装、任务、动作、结果和时间。

**验收**

- 同一任务连续收到多次“派发”请求，不产生多个执行租约。
- 终止后的任务不会被设备重新拉起。
- B 的手机不能通过猜测任务 ID 停止 A 的任务。

### MOB-09 决策中心

**要求**

- 展示当前账号全部待处理决策。
- 每个决策展示任务、项目、等级、问题、选项、AI 建议、影响范围和是否可逆。
- 支持批准、驳回和填写说明。
- 决策处理前必须确认账号仍有权限操作对应任务。
- 敏感决策要求面容/指纹/系统密码二次确认。
- 已验证的决策从待办移除，并展示续跑结果。
- 超时只允许提醒和升级通知，不允许自动批准。

**验收**

- A 的手机不能看到 B 的决策。
- 决策批准后任务正常续跑。
- 决策驳回后任务终止，待办立即消失。
- 同一决策重复批准不会产生第二次执行。

### MOB-10 推送与深链

**要求**

- iOS 使用 APNs。
- Android 使用 FCM 或可配置的国内厂商推送通道。
- 推送订阅绑定 `user_id + installationId`。
- 支持决策待处理、任务失败、设备失联、任务疑似卡住、任务完成五类通知。
- 推送正文只包含最少必要信息，不包含项目路径、完整日志、文档正文和敏感错误。
- 点击通知通过深链进入对应任务或决策。
- 深链只携带不可猜测引用，进入前重新校验登录和归属。
- 支持免打扰时段。
- 同一事件重复推送需要去重。
- 推送失败记录状态并按策略重试。
- 主机离线 60 秒后由公网在线监测服务发送离线推送；恢复心跳并稳定 30 秒后发送上线推送。
- 主机状态推送只发送给该主机所属账号已订阅的手机，不包含任务和项目数据。
- 业务事件推送由本地 Regent 发起，主机离线状态推送由公网在线监测发起。

**验收**

- A 的推送不会出现在 B 登录后的通知列表。
- 账号切换后旧推送令牌不再能触发 A 的通知展示。
- 决策通知可以直达决策详情。
- 电脑离线时，推送能说明离线原因。

### MOB-11 文件与图片上传

**要求**

- 支持相机拍照、相册选择、系统文件选择。
- 支持任务图片和任务文档。
- 上传前展示本地文件大小和类型校验结果。
- 上传过程可取消，失败可重试。
- 大文件不得阻塞页面其他操作。
- 单份文档上限 25MB，使用 2MB 分片上传。
- 分片支持断点续传，上传会话默认 24 小时有效。
- 分片以 `uploadSessionId + chunkIndex + chunkHash` 幂等。
- 全部分片完成后服务端校验文件总大小和 SHA-256，再绑定任务或文件库。
- Nginx 和中继的单请求上限至少为 32MB，文档分片请求不得超过 2MB。
- 文档是否保存到文件库由用户逐份决定。
- 上传接口必须校验账号、任务和项目归属。

**验收**

- App 可以从相册上传截图并从文件系统上传 PDF。
- B 不能向 A 的任务上传文件。
- 同一次上传断网后可明确重试，不生成两条成功记录。

### MOB-12 离线与网络恢复

**要求**

- App 明确区分无网络、中继离线、本地 Regent 离线和请求超时。
- 离线时允许保存本机任务草稿，但不显示为“已下发”。
- 恢复网络后自动刷新首页、任务详情和决策待办。
- 用户停留在详情页时，连接恢复能自动补齐最新状态。
- 推送深链在离线时保留目标位置，登录和联网后继续跳转。
- 离开页面后不能依赖前台轮询保持任务运行。

**验收**

- 关闭网络后新建任务，任务只保留为草稿。
- 重新联网后可以继续提交草稿。
- 电脑断网再恢复后，App 状态从离线切回在线。

### MOB-13 账号切换与设备撤销

**要求**

账号切换：

- 退出当前账号后，清理业务缓存、草稿、推送令牌和深链上下文。
- 新账号登录后，只加载新账号数据。

手机安装撤销：

- 用户可以在“账号与安全”中查看和撤销手机安装。
- 撤销后该安装的会话立即失效。
- 撤销操作不能撤销当前正在使用的安装，除非先二次确认并退出。

执行电脑撤销：

- 撤销后立即停止远程下发。
- 设备代理停止心跳。
- 当前活跃执行记录收敛为 `INTERRUPTED`。
- 对应任务进入 `CANCELLED`，原因记录为“执行电脑已被撤销”。
- 任务不自动转移到其他电脑，用户确认工作区状态后可手动重试。

**验收**

- 撤销手机安装后，旧会话无法继续访问。
- 撤销执行电脑后，旧设备令牌无法继续心跳或认领。
- 撤销后活动任务不会被另一台电脑自动接手。

### MOB-14 关于、诊断与反馈

**要求**

- 展示产品版本、完整发布码、后端版本、协议版本和运行环境。
- 提供“复制诊断信息”，内容脱敏。
- 诊断至少包含：安装 ID、账号 ID、App 版本、手机平台、连接状态、后端状态、设备状态、请求时间和错误分类。
- 不包含密码、Token、完整环境变量、项目文件内容和完整日志。
- 提供隐私政策、用户协议、开源许可和问题反馈入口。

**验收**

- 用户可在不打开桌面工作台的情况下复制可排查的诊断摘要。
- 诊断内容通过敏感信息扫描。

### MOB-15 账号注销

**要求**

- App 内提供账号注销入口。
- 注销前明确展示项目、任务、执行电脑、文件库、决策和推送将如何处理。
- 注销必须重新验证登录状态并二次确认。
- 注销成功后撤销全部手机安装、执行电脑绑定、Refresh Token 和推送订阅。
- 按审计和法务要求需要保留的数据必须去标识化。
- 注销过程中任何一步失败都要给出明确结果，不能只清本地缓存却显示账号已注销。

**验收**

- 用户可以在 App 内完成账号注销。
- 注销后旧 Access/Refresh Token 无法继续访问。
- 注销后该账号的执行电脑和手机安装全部失效。
- 注销后不再收到该账号的通知。

## 七、关键用户流程

### 1. 首次使用

```text
安装 App
  → 登录账号
  → 查看执行电脑状态
  → 扫描电脑端配对码
  → 绑定成功
  → 首页显示主机和 Codex 在线
```

### 2. 远程下发任务

```text
选择项目
  → 输入任务
  → 上传文档/图片
  → 选择立即派发或排队
  → 选择当前账号的在线执行电脑
  → 提交
  → 查看执行时间线
```

### 3. 远程决策

```text
收到推送
  → 打开决策详情
  → 查看风险和建议
  → 生物识别确认
  → 批准或驳回
  → 查看任务续跑或终止结果
```

### 4. 电脑离线

```text
App 检测失败
  → 展示具体离线原因
  → 保留本地草稿
  → 主机恢复后自动重连
  → 用户继续提交或查看任务
```

### 5. 切换账号

```text
退出账号 A
  → 清理 A 的业务缓存与推送
  → 登录账号 B
  → 只展示 B 的项目、任务、决策和电脑
```

## 八、多账号隔离验收矩阵

| 场景 | 期望结果 |
|---|---|
| A 手机查看设备列表 | 只返回 A 的执行电脑 |
| A 手机使用 B 的 deviceId 派发 | 返回“设备不存在” |
| B 电脑认领 A 的任务 | 返回“任务不存在” |
| B 电脑续租 A 的执行记录 | 拒绝 |
| B 电脑上报 A 的事件或结果 | 拒绝 |
| A 手机查看 B 的决策 | 返回“内容不存在或已失效” |
| B 登录后打开 A 的推送深链 | 不展示 A 的内容 |
| B 登录后查看通知列表 | 只展示 B 的通知 |
| A 退出后切换 B | A 的草稿、缓存和推送全部清除 |
| B 尝试绑定 A 已绑定的电脑 | 配对失败，不泄露电脑归属 |
| 撤销 A 的执行电脑 | 电脑立即失去设备接口权限 |

跨账号请求统一使用“不存在”语义，避免通过错误差异探测其他账号数据。

## 九、技术与架构边界

### 1. 推荐实现

- 使用 `Capacitor + Vue` 构建 iOS 与 Android App。
- 复用现有 Vue 页面中的业务 API 类型和状态守卫。
- 手机采用独立布局，不把桌面工作台直接封装成 WebView。
- 原生壳负责推送、生物识别、安全存储、相机、文件选择、深链和应用更新提示。

### 2. 网络结构

- 手机必须通过 HTTPS 域名访问公网中继。
- 中继只负责转发，不保存业务数据库，不执行 Codex。
- 公网在线监测只保存主机在线状态、账号订阅和推送令牌，不保存业务数据。
- 本地连接器主动长轮询公网中继。
- 所有业务权限在本地 Regent 服务端再次校验，中继和 App 都不是信任边界。

### 3. 登录与授权

- App 使用与浏览器会话分离的 Regent 手机 Bearer 会话。
- Access Token 有效期 30 分钟，Refresh Token 有效期 30 天并轮换。
- 敏感操作使用 5 分钟、一次性 Step-up Token。
- Nginx Basic Auth 不作为 App API 认证。
- 设备绑定、推送订阅、任务操作和决策操作都必须带账号会话。
- 写请求继续使用明确的业务 API，不接受任意路径透传。

### 4. 建议新增模型

| 模型 | 作用 |
|---|---|
| `mobile_installation` | 手机安装实例、所属账号、平台、App 版本和状态 |
| `mobile_push_subscription` | 用户、安装实例、推送通道、Token 和状态 |
| `device_pairing_code` | 一次性配对码、账号、电脑、有效期和使用状态 |
| `execution_device_credential` | 设备凭据摘要、签发时间、撤销时间和最后使用时间 |
| `execution_host_project` | 执行电脑与项目的显式授权、验证状态和失败原因 |
| `mobile_upload_session` | 分片上传会话、文件摘要、分片进度和过期时间 |
| `mobile_idempotency_key` | 客户端请求 ID、操作类型和幂等结果 |

执行电脑现有 `owner_id` 继续作为账号隔离根；不得改成“设备全局共享”。

### 5. 推送

- iOS 必须使用 APNs。
- Android 不能用常驻后台连接替代系统推送。
- Android 推送服务应做适配层，避免业务代码绑定单一厂商 SDK。
- 推送内容只传通知摘要和不可猜测引用。
- 主机在线/离线推送由公网在线监测服务触发，业务事件推送由本地 Regent 触发。
- 主机离线 60 秒判定，恢复后稳定 30 秒判定在线，防止抖动重复通知。

## 十、非功能要求

### 1. 性能

- 正常网络下冷启动到可操作首页 P90 不超过 3 秒。
- 首页数据刷新 P90 不超过 2 秒。
- 任务操作提交 P90 不超过 2 秒，不含服务器执行时间。
- 推送点击后 3 秒内进入目标页面，不含系统通道延迟。

### 2. 稳定性

- App 崩溃不会造成已提交任务丢失。
- 网络切换、后台恢复和锁屏解锁后状态可自动恢复。
- 重复点击、重复推送和重复深链不会造成重复任务或重复决策。

### 3. 安全

- 全链路 HTTPS。
- 令牌存 Keychain/Keystore。
- 敏感操作二次确认。
- 推送正文不包含敏感信息。
- 跨账号请求不泄露对象存在性。
- 日志和诊断信息必须脱敏。

### 4. 可访问性

- 支持系统字体缩放。
- 按钮、状态和输入框有可读的无障碍标签。
- 颜色不是唯一状态表达方式。
- 触摸目标尺寸满足 iOS/Android 常规可用性要求。

## 十一、App 分发与上线要求

### 1. iOS

- 内测通过 TestFlight。
- 正式版通过 App Store 审核。
- 需要 Apple Developer 账号、隐私政策、应用截图、审核说明和推送证书。
- 不能承诺像桌面安装包一样直接下载安装。

### 2. Android

- 内测提供签名 APK。
- 正式版准备 AAB、签名 APK 和商店素材。
- 可发布到官网、Google Play 和国内应用商店。
- 不得提供未签名或调试签名包。

### 3. 国内合规

- 公网服务需要 HTTPS 域名和有效证书。
- 根据实际部署情况完成 ICP 备案和 App 备案。
- 提供隐私政策、用户协议、账号注销和权限说明。
- 相机、相册、通知权限按需申请，不能首次启动全部索取。

### 4. App Store 风险

纯 WebView 包装可能被认定功能不足。首版必须包含：

- 原生推送与通知深链。
- 生物识别解锁。
- 原生文件/相机上传。
- 本地离线草稿。
- 原生设备绑定。

## 十二、验收场景

### 场景 1：手机下发任务

- **Given** 账号 A 已登录且执行电脑在线
- **When** A 在手机创建任务并选择自己的电脑
- **Then** 任务成功进入待执行或排队
- **And** 电脑设备代理可以领取
- **And** App 能实时看到状态变化

### 场景 2：跨账号派发

- **Given** A 手机登录，B 电脑在线
- **When** A 使用 B 的 deviceId 派发任务
- **Then** 返回“设备不存在”
- **And** B 的设备代理不产生任何任务

### 场景 3：跨账号认领

- **Given** A 的任务处于待执行
- **When** B 电脑使用自己的合法设备令牌请求认领
- **Then** 平台返回“任务不存在”
- **And** B 无法创建执行记录或租约

### 场景 4：远程决策

- **Given** A 的任务等待 L2 决策
- **When** APNs/Android 推送到达 A 的手机
- **Then** 点击通知进入决策详情
- **And** A 完成生物识别后可批准
- **And** 任务恢复执行
- **And** B 的手机和电脑看不到该决策

### 场景 5：电脑离线

- **Given** 执行电脑断网
- **When** A 打开手机 App
- **Then** 首页显示“执行电脑已离线”及检查建议
- **And** 未提交任务只能保存为草稿
- **And** 网络恢复后主页自动恢复在线

### 场景 6：切换账号

- **Given** A 正在使用 App 并收到 A 的推送
- **When** A 退出并登录 B
- **Then** A 的业务缓存、草稿和推送绑定被清除
- **And** B 只看到 B 的数据
- **And** 点击 A 的历史深链不显示 A 的内容

### 场景 7：撤销执行电脑

- **Given** A 的手机已绑定执行电脑
- **When** A 在 App 中撤销该电脑
- **Then** 设备凭据立即失效
- **And** 电脑不能继续心跳、认领或上报
- **And** 手机设备列表显示已撤销

## 十三、埋点与运营指标

| 指标 | 定义 |
|---|---|
| 远程操作成功率 | 手机提交任务、决策、停止、重试成功次数 / 总尝试次数 |
| 推送打开率 | 点击推送并打开目标页次数 / 推送成功展示次数 |
| 决策响应时长 | 推送到达至决策完成的时间 |
| 主机在线率 | 执行电脑四健康项均正常的时长 / 统计时长 |
| 离线诊断准确率 | App 展示离线原因与后端事实一致的比例 |
| 跨账号串号数 | 必须恒为 0 |
| App 无崩溃会话比例 | 未发生崩溃的会话 / 总会话 |

埋点不得包含任务正文、日志、密码、Token、文档内容或项目路径。

## 十四、风险与依赖

| 风险 / 依赖 | 影响 | 建议 |
|---|---|---|
| iOS 后台不能保持常驻连接 | 不能靠轮询及时通知 | 强制使用 APNs |
| Android 厂商推送差异大 | 部分机型收不到通知 | 推送适配层 + 通道健康检测 |
| 执行电脑休眠或关机 | 手机无法下发或执行 | 提供主机守护与明确离线提示，不承诺关机执行 |
| 纯 WebView 审核风险 | iOS 可能拒绝上架 | 增加原生推送、生物识别、文件上传和离线草稿 |
| 多用户账号切换残留 | 可能发生串号 | 本地数据按账号分区，切换时强制清理 |
| 中继增加在线监测状态 | 不再是完全无状态 | 只保存主机状态与推送订阅，不保存任何业务数据 |
| 推送供应商尚未落地 | 影响开发和发版 | 技术评审确定 APNs 与 Android 推送适配器 |
| 域名、备案和证书尚未准备 | 影响上架与真机测试 | 进入正式开发前完成公网环境准备 |
| 分片上传实现复杂 | 增加服务端和 App 工作量 | 先做上传会话、分片幂等和断点续传技术验证 |

## 十六、完成定义

本需求完成必须同时满足：

1. Android 和 iOS 均可安装并通过核心流程验收。
2. 手机可独立完成新建、派发、监控、停止、重试和决策。
3. 决策/失败/完成推送可到达，主机离线和恢复上线也能收到推送，并能通过深链进入正确页面。
4. 多账号隔离验收矩阵全部通过，跨账号串号为 0。
5. 主机离线、连接器断开和 Codex 不可用均有明确状态和操作建议。
6. 账号切换、设备撤销和推送解绑经过真实双账号测试。
7. 文档分片上传、断点续传、文件库保存和失败重试通过真实弱网验收。
8. 账号注销、隐私政策、权限说明、诊断脱敏和发布材料准备完成。
