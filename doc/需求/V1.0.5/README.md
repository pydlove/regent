## 一、版本定位

V1.0.5 只规划一个需求：

> **REG-V105-MOB：Regent 手机 App 与多账号设备隔离。**

目标不是把桌面工作台简单搬到手机，而是让用户在离开电脑后，仍能通过 Android 或 iOS
App 完成远程任务下发、执行监控、异常处理和 L2/L3 决策。

本版本主题：

> **人离开电脑，控制权不离开。**

产品标语：

> **电脑不在身边，AI 任务随时随地开工。**

## 三、产品组成

```text
Android / iOS App
        │ HTTPS
        ▼
公网中继（转发 + 最小 presence，不执行业务逻辑）
        ▲
        │ 本机主动长轮询
        │
执行电脑：连接器 + 设备代理 + 本地 Regent + Codex
```

手机是控制端，不是执行端：

- 任务、代码、数据库、Codex 和工作区继续留在执行电脑。
- 手机通过公网中继访问本地 Regent。
- 手机不获得任意 Shell、文件系统或桌面控制能力。
- 电脑完全关机且无法远程唤醒时，App 只能如实显示离线，不能假装任务已执行。

## 四、首版必须具备的五条底线

1. **双端可安装**：提供 Android APK/AAB 与 iOS TestFlight/App Store 版本。
2. **远程可操作**：手机能新建、派发、监控、终止和重试任务。
3. **决策能送达**：L2/L3 决策通过系统推送或配置的推送通道到达手机，并可在 App 内处理。
4. **多用户不串号**：账号、手机安装、执行电脑、项目、任务五层强隔离。
5. **离线不欺骗**：电脑、连接器、设备代理或 Codex 任一不可用时，App 明确展示原因和下一步。

## 五、本版本明确不做

- 不做团队、组织、角色和跨账号项目共享。
- 不做一台执行电脑同时绑定多个账号。
- 不做手机端执行 Codex 或修改项目工作区。
- 不做远程桌面、任意 Shell、文件管理器或 VPN。
- 不做跨账号共享任务、决策、文件库、环境信息和推送。
- 不把 MySQL、Codex、项目文件或数据库凭据迁到公网服务器。
- 不做通用 IM、审批中台或复杂多级审批流。
- 不承诺设备关机、断网或休眠时任务仍能执行。

## 七、发布策略

1. **内测阶段**
   - Android：签名 APK，小范围安装。
   - iOS：TestFlight 内测。
   - 只验证账号隔离、远程下发、执行监控、推送决策四条主链路。
2. **正式阶段**
   - iOS：提交 App Store。
   - Android：官网 APK，按需要提交 Google Play 或国内应用商店。
   - 完成 HTTPS 域名、隐私政策、ICP 备案、App 备案和推送服务配置。

## 八、已确认的关键决策

1. 主机离线和上线由公网侧在线监测触发推送，手机同时可实时读取主机状态。
2. 文档使用 25MB 上限、2MB 分片、断点续传和 24 小时上传会话。
3. 手机使用 Bearer + Refresh + Step-up Token，不使用 Basic Auth 作为 App 认证。
4. 项目与执行电脑建立显式授权，并验证项目目录与 Codex。
5. 执行电脑配对使用二维码加电脑端二次确认。
6. 生物识别/系统密码是正式上架必须具备的能力。
7. 最低系统版本为 iOS 15、Android 9。
8. App 内提供账号注销入口。
9. 首页固定展示产品标语“电脑不在身边，AI 任务随时随地开工”。
