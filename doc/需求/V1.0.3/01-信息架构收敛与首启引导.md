# 信息架构收敛与首启引导需求说明书

| 项目 | 内容 |
|---|---|
| 需求编号 | REG-V103-IA |
| 优先级 | P0-1 |
| 文档版本 | v0.1 |
| 状态 | 待评审 |
| 编写日期 | 2026-10-20 |
| 依赖需求 | 无 |

## 一、背景与问题

当前产品按技术实体组织导航，一级菜单同时出现工作台、任务、决策、计划、部署、服务器、测试用例、项目、环境和插件。用户必须理解系统内部的领域划分，才能判断一个功能应该去哪里找。

主要问题：

1. 一级菜单过多，功能入口与资源入口混在一起。
2. 计划、测试、部署属于不同工作阶段，却与任务平级。
3. 服务器、环境、插件是项目资源，却占据一级菜单。
4. 决策和失败通知是“待处理事项”，却要求用户主动进入不同页面寻找。
5. 新用户第一次登录后没有明确的主流程，不知道应该先注册项目、连接设备还是录入任务。
6. 产品能力不断增加后，用户对功能是否存在的认知反而下降。

## 二、需求目标

### 1. 业务目标

- 将一级导航从约 10 项收敛到 4 项加底部设置。
- 让用户按“工作目标”而不是“系统实体”找到功能。
- 让新用户首次进入时只面对一条明确主流程。
- 将需要用户处理的事项集中到统一待办入口。
- 保持所有已有能力可访问，不因导航调整丢失功能。

### 2. 用户体验目标

- 新用户无需阅读帮助文档即可找到新建任务入口。
- 用户工作台首屏可以看出下一步需要自己处理什么。
- 用户最多通过两步操作进入任一核心业务页面。
- 用户不再需要记忆“服务器、环境、插件”分别在哪里。

### 3. 非目标

- 不重做现有业务页面视觉。
- 不改变任务、部署、环境等领域的业务规则。
- 不通过隐藏功能来实现“菜单变少”。
- 不在本需求中实现团队角色和权限系统。

## 三、目标用户

| 用户 | 主要目标 | 当前痛点 |
|---|---|---|
| 新用户 | 尽快完成第一次任务录入和执行 | 不知道从哪里开始 |
| 日常操作者 | 查看任务、处理决策、检查执行 | 入口分散，需要多页面切换 |
| 项目管理员 | 配置项目、服务器、环境、插件 | 资源与业务流程混在一起 |
| 交付负责人 | 测试、部署和查看发布结果 | 测试与部署分散在多个菜单 |

## 四、目标信息架构

### 1. 一级导航

| 菜单 | 定位 | 包含能力 |
|---|---|---|
| 工作台 | 当前状态和待办中心 | 执行控制塔、项目概览、我的待办、异常和首启引导 |
| 任务 | 计划与执行工作流 | 需求、任务、计划、执行记录 |
| 交付 | 验证与发布工作流 | 测试用例、部署配置、发布记录 |
| 项目 | 项目及其资源 | 项目资料、服务器、环境、能力插件 |
| 设置 | 系统和账户配置 | 固定在侧边栏底部，不计入主业务菜单 |

### 2. 全局项目选择

顶栏继续保留全局项目选择器。

规则：

- 项目选择影响工作台、任务、交付和项目页的默认筛选。
- 跨项目全局搜索不受当前项目选择限制。
- 项目选择结果继续支持刷新后恢复。

### 3. 全局待办

新增顶栏“待办”入口，合并以下事项：

- 待人工决策。
- 执行失败且需要处理。
- 执行卡住或设备失联。
- 待用户确认的计划、需求拆解或其他动作。
- 系统通知。

入口显示可操作事项数量，不统计普通完成信息。

点击待办后打开工作台中的待办侧栏或完整待办页面。

### 4. 原有功能迁移

| 原入口 | 新位置 | 迁移规则 |
|---|---|---|
| 决策 | 工作台“我的待办”与顶栏待办 | 决策页保留路由，不作为一级菜单 |
| 计划 | 任务 → 计划 | 计划创建、执行和结果保持现有能力 |
| 测试用例 | 交付 → 测试用例 | 测试执行记录同步进入执行控制塔 |
| 部署 | 交付 → 部署 | 部署列表和详情保持现有能力 |
| 服务器 | 项目 → 资源 → 服务器 | 支持跨项目查看时通过筛选进入 |
| 环境 | 项目 → 资源 → 环境 | 保留全局环境和多项目环境能力 |
| 插件 | 项目 → 资源 → 能力插件 | 保留现有插件启停和版本能力 |

### 5. 旧路由兼容

所有旧路由必须继续可访问，并通过前端重定向到新位置。

示例：

- `/decisions` → 工作台待办中的决策视图。
- `/plans` → `/tasks?view=plans`。
- `/deployments` → `/delivery?view=deployments`。
- `/servers` → `/projects?view=servers`。
- `/environments` → `/projects?view=environments`。
- `/plugins` → `/projects?view=plugins`。

具体 URL 以实现设计为准，但旧地址不能返回 404。

## 五、首启引导

### 1. 触发条件

首次登录且用户尚未完成引导时，在工作台展示首启引导区域。

每个账号独立保存引导状态。

### 2. 主流程

`注册项目 → 连接执行设备 → 创建第一个任务 → 处理首次审批`

### 3. 步骤规则

| 步骤 | 完成条件 | 未完成提示 |
|---|---|---|
| 注册项目 | 当前账号至少有一个可用项目 | 提供注册项目入口 |
| 连接执行设备 | 至少有一台已配对设备在线且 Codex 可用 | 提供设备检测、下载和配对入口 |
| 创建第一个任务 | 当前账号至少成功创建一个任务 | 提供新建任务入口 |
| 处理首次审批 | 用户至少处理过一次决策或明确不存在待审批时跳过 | 跳转到对应决策 |

### 4. 交互要求

- 首启引导不是阻塞式多步弹框。
- 用户可以跳过引导，跳过状态要记录。
- 用户可以从工作台重新打开引导。
- 每一步完成后立即更新状态，不要求刷新页面。
- 系统已有项目、设备或任务的老用户，应根据真实状态自动标记相应步骤完成。
- 没有待审批事项时，不应让用户误以为流程未完成。

### 5. 渐进展示

首启期间优先展示主流程入口。

计划、测试、部署、插件等高级能力仍可从对应菜单进入，但不在首次进入时主动弹出说明。

## 六、功能需求

### IA-01 一级导航收敛

系统只展示四个主业务菜单和底部设置。

验收：

- 桌面端侧边栏主业务菜单数量不超过 4。
- 当前页面高亮正确。
- 折叠侧边栏后仍能识别菜单图标和名称。
- 移动端使用抽屉导航，菜单层级一致。

### IA-02 工作台待办化

工作台首屏必须优先展示“需要我处理的事项”，其次展示执行状态和项目概览。

待办支持：

- 查看数量。
- 按类型筛选。
- 点击进入对应详情。
- 处理后数量实时更新。

### IA-03 全局待办角标

顶栏待办入口显示可操作事项数量。

规则：

- 数量为 0 时不显示角标或显示中性状态。
- 普通系统通知不计入待办数量。
- 同一对象的重复通知不能重复计数。
- 待办处理完成后，角标在合理时间内更新。

### IA-04 功能迁移与重定向

原菜单对应功能必须可从新位置完整访问。

验收：

- 旧地址不会 404。
- 深链打开后，页面能够定位到正确的页签和对象。
- 通知中的旧链接继续有效。

### IA-05 全局搜索

提供统一搜索入口，至少支持：

- 页面功能。
- 项目。
- 任务编号和标题。
- 部署名称。
- 执行记录。

V1.0.3 不要求实现复杂自然语言搜索。

搜索结果必须标明所属业务模块，并支持键盘打开。

### IA-06 首启引导

按账号保存引导状态，并支持自动推断已完成步骤。

验收：

- 新用户首次登录能看到明确主流程。
- 已完成步骤立即打勾。
- 刷新后状态不丢失。
- 用户可跳过并重新打开。

### IA-07 导航埋点

记录以下产品事件：

- 菜单点击。
- 全局搜索打开和搜索成功。
- 待办打开及处理。
- 首启引导步骤完成、跳过和重新打开。

埋点不得包含密码、Token 或完整任务正文。

## 七、页面与交互要求

### 1. 侧边栏

- 工作台、任务、交付、项目按业务顺序排列。
- 设置固定在底部。
- 不使用多层悬浮菜单。
- 当前项目和当前页面的关系要清晰。

### 2. 工作台

建议结构：

1. 首启引导或当前状态摘要。
2. 我的待办。
3. 执行控制塔。
4. 项目概览和最近结果。

大卡片只用于需要用户立即处理的内容，不使用大量同尺寸统计卡片占满首屏。

### 3. 任务页

任务页使用页签区分：

- 全部任务。
- 待执行。
- 执行中。
- 待决策。
- 需求。
- 计划。

页签和筛选必须共享同一数据源，不能形成重复列表。

### 4. 交付页

交付页使用页签区分：

- 测试用例。
- 部署。
- 发布记录。

测试和部署的执行详情复用执行控制塔组件。

### 5. 项目页

项目页展示项目基本资料，并提供资源页签：

- 服务器。
- 环境。
- 能力插件。

跨项目资源可通过筛选查看，不需要回到一级菜单。

## 八、业务规则

1. 菜单调整不改变任何历史数据的归属关系。
2. 决策仍保留独立对象和现有分级规则，只改变入口位置。
3. 计划、测试、部署的执行状态仍由各自业务流程管理。
4. 全局待办只负责聚合和跳转，不复制业务对象。
5. 旧路由迁移必须可回退，不能在一次发布中直接删除。
6. 首启引导完成状态不得阻止用户正常使用其他功能。

## 九、非功能需求

- 导航切换不产生整页白屏。
- 新路由重定向不丢失查询参数和深链对象。
- 工作台首屏主要数据接口失败时，不影响其他页面使用。
- 待办角标更新延迟不超过 30 秒。
- 首启引导状态写入失败时，不应阻断用户操作。
- 移动端抽屉导航与桌面端菜单结构一致。

## 十、验收场景

### 场景 1：新用户进入系统

**Given** 用户第一次登录且没有项目和设备  
**When** 进入工作台  
**Then** 页面展示“注册项目”为下一步，并明确说明后续步骤  
**And** 不弹出多个功能引导弹框

### 场景 2：老用户已有项目

**Given** 用户已有可用项目和在线设备  
**When** 进入工作台  
**Then** 首启引导自动将前两步标记完成  
**And** 直接提示创建第一个任务或处理待办

### 场景 3：通过旧链接访问部署

**Given** 用户打开旧 `/deployments` 地址  
**When** 页面加载  
**Then** 自动进入“交付 → 部署”  
**And** 页面内容和筛选项保持可用

### 场景 4：全局待办数量

**Given** 用户有 2 条待决策和 1 条卡住执行  
**When** 打开任意业务页面  
**Then** 顶栏待办入口显示 3  
**And** 点击后能进入对应详情

### 场景 5：功能迁移完整性

**Given** 用户需要使用服务器和环境  
**When** 进入项目资源页  
**Then** 仍可以完成原有新增、编辑、多项目关联和删除操作

## 十一、成功指标

| 指标 | 目标方向 |
|---|---|
| 一级菜单数量 | 不超过 4 项 |
| 新用户首次创建任务耗时 | 明显下降 |
| 无帮助完成核心路径比例 | 持续提升 |
| 菜单相关功能查找失败反馈 | 明显下降 |
| 旧链接 404 数量 | 0 |
| 全局待办点击处理率 | 持续提升 |

## 十二、风险与待确认项

| 风险或问题 | 影响 | 建议 |
|---|---|---|
| 用户已习惯旧菜单位置 | 短期找不到功能 | 提供旧路由兼容和一次性迁移提示 |
| 决策不再是独立菜单 | 核心能力被低估 | 使用顶栏待办角标和工作台首屏持续强化 |
| 项目资源页过重 | 项目管理复杂 | 使用页签按资源类型拆分 |
| 首启步骤判断过于复杂 | 状态不准确 | 以真实业务对象存在性判断，不保存虚假的流程状态 |
| 全局搜索范围过大 | 延期 | V1.0.3 只支持明确对象和页面，不做语义搜索 |
