# Regent V1.0.4 技术评审

| 项目 | 内容 |
|---|---|
| 需求版本 | Regent_V1.0.4_R100B014 |
| 评审日期 | 2026-10-21 |
| 当前主线 | REG-V104-EXE 执行可靠性中心 |
| 状态 | EXE 核心切片已发布 B002，OBS/DLV 待后续迭代 |

## 一、依赖关系

```text
REG-V104-EXE（状态、设备、租约、恢复、诊断）
        ↓
REG-V104-OBS（只消费 EXE 的统一事实）
        ↓
REG-V104-DLV（复用执行状态、设备检查和诊断）
```

- EXE 是唯一状态事实源，OBS 和 DLV 不得根据页面字段或日志关键词另行推断业务状态。
- OBS 的时间线、失败摘要和诊断复制必须消费 EXE 产生的稳定事件与诊断读模型。
- DLV 的预检、部署进度和失败建议复用同一套设备健康、执行阶段和诊断分类。

## 二、评审决策

1. **健康状态采用“持久化事实 + 读时推导”**：设备最后心跳、执行租约、最后事件时间落库；
   正常、缓慢、疑似卡住、设备失联由统一读模型推导，不保存第二份可漂移的健康状态。
2. **设备按账号级注册，任务按项目过滤**：当前设备令牌已绑定账号，项目归属由接口层校验；
   同一任务运行中不允许直接换设备，设备实例重启后由平台收敛旧租约并重新排队。
3. **同一任务只允许一条活跃执行**：认领使用任务行锁；`task_run.active_task_id` 生成列加唯一索引
   作为数据库最后防线。重复心跳或并发认领不能产生第二条 `RUNNING` 记录。
4. **服务端接单前必须自检**：校验设备在线、Codex 可用、项目目录存在和项目启用状态。检查失败
   不创建执行记录、不消耗执行位，并返回用户可执行的中文原因。
5. **设备代理以实例号区分进程重启**：同一 `device_id` 换新 `agent_instance_id` 时，旧租约立即
   标记为中断、任务回到 `QUEUED`、进程内执行位同步释放。
6. **Runtime 保持固定 Shell + 增量 Runtime**：下载后校验大小、SHA-256、签名和包内版本；首次启动
   健康确认前保持 `pending`，失败自动回滚并记录失败发布码，同一发布码不再重复提示。
7. **诊断由应用层统一生成**：失败分类、最后成功阶段、失败阶段、可重试性、换设备/人工决策建议
   和脱敏摘要从执行记录与事件流推导，前端不得自行猜测。

## 四、数据库与迁移

- `V37__execution_reliability_context.sql`
  - 新增 `execution_device`；
  - `task_run` 增加设备、最后心跳、最后事件时间；
  - 新增 `active_task_id` 生成列与单任务活跃执行唯一索引；
  - 迁移前自动收敛历史重复 `RUNNING` 记录。
- `V38__device_agent_instance_recovery.sql`
  - `execution_device` 增加代理进程实例号，用于客户端重启恢复。
- `V39__task_documents_and_file_library.sql`
  - 新增 `task_document` 与 `file_library_document`；
  - 文件库按项目与内容哈希去重，任务文档可引用文件库条目；
  - 支持新建任务时上传一次性文档，或逐份选择保存到文件库供以后复用。

既有 `V1`～`V36` 未修改。

## 六、测试策略

- `regent-core`：任务认领竞态、设备租约持有者、接单自检、设备实例重启、诊断分类与脱敏。
- `regent-interfaces`：设备协议 DTO、账号归属校验、设备心跳与任务协议。
- `regent-boot` + `regent_test` MySQL：Flyway、设备心跳幂等落库、单任务活跃执行唯一约束、
  Agent 协议完整往返。
- `regent-desktop`：Codex 探测、执行中事件、并发上限、Runtime 包依赖、失败版本去重、
  Runtime 健康确认。
- `regent-web`：类型检查、UI 约定检查、生产构建。

## 七、剩余风险

1. 设备最低 Shell/Runtime 版本约束尚未形成服务端强制规则；需要随 V1.0.4 发布清单确定最低版本。
2. 设备实例重启恢复目前依赖新版设备代理上报 `agentInstanceId`；旧客户端只走原有租约超时路径。
3. 全量 `*IT` 中 `TaskLifecycleIT` 与 `ExecutionControlTowerPersistenceIT` 存在与本版本无关的
   既有测试数据缺陷，应单独开 Bug 单处理，不在 EXE 中顺手修改。
4. 设备自检失败后的重复投递冷却尚未做服务端持久化；当前由设备代理失败退出和用户修复后重试控制。
