# 项目级一键交付闭环需求说明书

| 项目 | 内容 |
|---|---|
| 需求编号 | REG-V104-DLV |
| 优先级 | P0-3 |
| 文档版本 | v1.0 |
| 状态 | 待技术评审 |
| 编写日期 | 2026-10-20 |
| 依赖需求 | REG-V104-EXE、REG-V104-OBS |

## 一、背景与问题

Regent 已有项目、环境、服务器、部署脚本和版本发布能力，但用户完成一次真实交付仍然需要理解并手工串联多个对象：

1. 项目、环境、服务器和部署配置分散在不同页面。
2. 部署脚本的路径、目标目录、权限和变量容易配置错误。
3. 发布前没有统一的环境检查，问题往往在执行后才暴露。
4. 部署失败后，用户难以判断是脚本、服务器、网络、构建还是版本问题。
5. 发布过程中可能出现版本已改、部署失败、线上状态不明确。
6. 一次部署和对应任务、版本、服务器之间缺少完整追溯。
7. 新项目首次交付需要反复试错。

V1.0.4 需要让用户从“项目已经准备好”直接走到“安全上线并可追溯”，而不是把工作留给命令行和人工记忆。

## 二、目标

### 1. 业务目标

- 降低首次部署和重复部署的配置成本。
- 提高部署一次成功率。
- 部署失败时不破坏线上可用版本。
- 部署、发布、任务和执行记录可以互相追溯。
- 把交付从“会写脚本的人才能操作”降低为“了解项目的人可以操作”。

### 2. 用户体验目标

- 用户在一个交付流程中完成项目、环境、服务器和目标目录选择。
- 发布前明确看到阻断项和可修复动作。
- 执行过程中看到阶段进度，不需要盯着终端。
- 失败后看到失败阶段、影响和建议。
- 可以恢复上一次成功版本。

### 3. 非目标

- 不实现通用 Kubernetes 控制台。
- 不实现复杂多环境审批链。
- 不替代专业 CI/CD 平台的构建能力。
- 不允许 AI 在未确认的情况下改生产服务器。
- 不在本版本实现跨项目联合发布。

## 三、核心概念

### 1. 交付上下文

一次交付由以下对象组成：

- 项目。
- 环境。
- 服务器。
- 发布脚本。
- 目标目录。
- 版本或构建产物。
- 执行设备和执行器。
- 本次部署记录。

这些对象必须在开始前完整确定，任何缺失项都必须进入预检结果，不允许到执行中才发现。

### 2. 交付阶段

统一阶段：

1. 上下文确认。
2. 环境预检。
3. 构建或打包。
4. 上传产物。
5. 执行远端脚本。
6. 健康检查。
7. 发布确认。
8. 完成或回滚。

每个阶段都要生成用户可读摘要和技术详情。

### 3. 发布状态

| 状态 | 含义 |
|---|---|
| 草稿 | 配置尚未完成，不能执行 |
| 预检中 | 正在检查依赖和服务器 |
| 待确认 | 预检通过，等待用户确认 |
| 执行中 | 正在构建、上传或执行脚本 |
| 验证中 | 正在做健康检查 |
| 已完成 | 发布成功并记录版本 |
| 失败 | 执行失败，等待处理 |
| 已回滚 | 已恢复上一成功版本 |

## 四、功能需求

### DLV-01 项目级交付入口

用户从项目或交付页发起交付时，系统自动带出当前项目。

规则：

- 当前项目明确时默认选中当前项目。
- 一个部署或环境可以关联多个项目，但本次交付只能有一个主项目。
- 项目未注册或项目目录不可用时阻断交付。
- 切换项目后服务器、环境、脚本和目标目录重新校验。

验收：

- 从项目页进入新建交付时默认选中当前项目。
- 切换项目不会保留上一个项目的服务器和目标目录。
- 没有可用服务器时显示具体缺失项，不自动猜测。

### DLV-02 统一预检

执行前必须生成结构化预检结果。

检查项：

- 项目路径是否存在。
- 项目是否有可用的发布脚本。
- 脚本是否非交互执行。
- 脚本是否包含规范要求的目标目录、环境变量和健康检查。
- 服务器是否可达。
- 凭据是否有权限。
- 目标目录是否可写。
- 本地构建或打包依赖是否满足。
- 目标环境是否支持本次版本。
- 当前 Runtime 和设备代理是否可用。

预检结果分为：

- 阻断项。
- 警告项。
- 通过项。

验收：

- 有阻断项时不能开始部署。
- 每个阻断项提供修复入口或明确命令说明。
- 预检通过后生成可追溯的执行上下文。

### DLV-03 部署脚本校验

脚本校验必须在服务端和客户端执行前分别生效，不能只依赖前端提示。

校验内容：

- 是否支持非交互执行。
- 是否通过环境变量接收敏感信息。
- 是否把密码写入命令参数或日志。
- 是否有明确的远端目录变量。
- 是否处理失败退出码。
- 是否包含健康检查或可由平台补充。
- 是否检测上传产物与脚本期望一致。

验收：

- 不符合规范的脚本不能执行。
- 校验失败展示具体行号和问题。
- 修正后无需重新创建整个部署。

### DLV-04 交付执行与进度

执行过程必须展示阶段化进度：

- 正在预检。
- 正在构建。
- 正在上传。
- 正在执行远端脚本。
- 正在健康检查。
- 正在记录版本。

每个阶段包含：

- 开始时间。
- 结束时间。
- 成功或失败。
- 用户可读摘要。
- 可展开技术详情。

验收：

- 进度窗口固定尺寸，不因日志增加而撑高。
- 失败后保留已成功阶段。
- 关闭窗口后可以从部署记录恢复查看。
- 刷新页面不会丢失执行记录。

### DLV-05 失败处理与回滚

部署失败时必须明确：

- 失败阶段。
- 是否已影响线上。
- 是否需要回滚。
- 回滚目标和回滚结果。

规则：

- 上传失败不能覆盖当前线上产物。
- 服务重启失败应自动尝试恢复上一版本。
- 回滚动作必须二次确认并留痕。
- 回滚成功后状态显示“已回滚”，不能显示“已完成”。
- 回滚失败必须进入人工处理状态，不能静默重试。

验收：

- 发布失败后线上仍运行上一成功版本。
- 用户能看到失败原因和当前线上版本。
- 回滚过程有阶段日志和结果。

### DLV-06 版本与发布记录

每次成功交付必须记录：

- 发布版本。
- 发布码。
- 项目。
- 环境。
- 服务器。
- 脚本版本或摘要。
- 构建产物摘要。
- 执行设备。
- 操作者。
- 开始和完成时间。
- 关联任务或需求。

版本信息必须统一使用 `Regent_` 前缀。

验收：

- 从历史记录可以定位到对应任务。
- 同名版本不能无提示覆盖。
- 失败记录和成功记录都保留。
- 敏感凭据不进入记录。

### DLV-07 交付异常建议

系统根据失败阶段提供建议，至少覆盖：

- 项目路径不存在。
- 脚本规范不通过。
- 服务器连接失败。
- 权限不足。
- 上传失败。
- 服务重启失败。
- 健康检查失败。
- Codex 或设备代理不可用。

建议必须可操作，不能只显示错误文本。

## 五、用户流程

```text
选择项目
  → 选择环境
  → 选择服务器
  → 选择发布脚本和目标目录
  → 执行预检
  → 修复阻断项
  → 确认交付
  → 构建、上传、部署、健康检查
  → 成功记录或失败回滚
```

## 六、技术边界

- 部署执行继续通过 `DeploymentExecutor` 等端口抽象，不把 SSH、HTTP 或 shell 类型带入核心域。
- 预检结果使用结构化 DTO，前后端共享同一套阻断项定义。
- 脚本规范校验必须在后端再次执行，前端校验只用于即时反馈。
- 服务器凭据只通过加密配置或环境变量传递，不进入命令行参数、日志和数据库明文。
- 部署记录和版本记录必须能在服务重启后恢复。
- 交付工作台复用执行可靠性中心的状态和执行工作台时间线。

## 七、验收场景

### 场景 1：当前项目新建交付

**Given** 顶栏已选择项目 A  
**When** 用户点击新建交付  
**Then** 项目 A 自动选中  
**And** 环境、服务器、脚本和目标目录均在项目 A 范围内校验

### 场景 2：脚本包含密码参数

**Given** 用户上传包含 `-p password` 的发布脚本  
**When** 执行预检  
**Then** 部署被阻断  
**And** 页面显示具体问题行和改用环境变量的修复建议

### 场景 3：上传后服务重启失败

**Given** 新产物已上传，服务重启失败  
**When** 执行失败处理  
**Then** 系统提示回滚上一成功版本  
**And** 回滚完成后线上版本恢复  
**And** 记录显示“已回滚”

### 场景 4：交付历史追溯

**Given** 用户查看一次成功交付  
**When** 打开记录详情  
**Then** 能看到版本、环境、服务器、脚本摘要、执行设备和关联任务  
**And** 可以打开对应任务的执行时间线

## 八、成功指标

| 指标 | 衡量方式 |
|---|---|
| 首次交付成功率 | 新项目第一次部署成功的比例 |
| 预检阻断率 | 预检提前发现并阻断的问题比例 |
| 一次部署成功率 | 不因配置问题重复重试的比例 |
| 失败回滚成功率 | 失败后恢复上一版本的比例 |
| 交付平均配置时间 | 从新建交付到开始执行的时间 |
| 交付记录可追溯率 | 成功记录可关联到版本和任务的比例 |

## 九、风险与待确认项

| 风险 | 影响 | 建议 |
|---|---|---|
| 项目和环境多对多关系 | 默认选项可能不符合用户预期 | 本次交付只允许一个主项目 |
| 生产发布直接执行 | 误操作风险高 | 高风险操作二次确认并保留回滚 |
| 脚本历史版本不统一 | 预检规则误杀旧脚本 | 区分旧脚本兼容模式和新规范模式 |
| 服务器凭据泄露 | 严重安全问题 | 禁止密码进入命令和日志，统一脱敏 |
| 回滚服务不可用 | 线上不可恢复 | 回滚失败进入人工处理并保留现场 |
